## 1. 무엇이 막혀 있나 — 실측

```
data/approved/labor-mappings.json    매핑 1,331건 전부 confirmed: false
schema.ts:114                        confirmed: z.literal(false)   ← true 가 들어갈 수 없다
calculateLabor.ts:121                !mapping.confirmed → blocking: true 경고
```

**거의 모든 견적 행에 `mapping-unconfirmed` 차단 경고가 뜬다.**
`priceQuote.ts:82` 도 *"품셈 경고에는 `mapping-unconfirmed` 가 거의 항상 들어 있다"* 고 적고 있다.

### 화면에는 그것을 풀 수단이 없다

```
LaborMode = 'mapped' | 'manual' | 'not-applicable' | 'unresolved'    타입은 있다
manualLaborUnitPrice · overrideReason                                 필드도 있다

QuoteSheet.tsx:160·239   not-applicable 을 **표시만** 한다
                         설정하는 버튼·입력이 없다
```

→ **작업 파일 JSON 을 손으로 고치지 않으면 견적을 완결할 수 없다.**
  그것은 기계적 시험용 우회일 뿐 제품 완료가 아니다.

## 2. 설계 제안 — 기존 정책으로 정할 수 있는 것은 여기서 정한다

Codex 요청: *"기존 정책·사용자 지시로 정할 수 있는 구현사항은 또 묻지 말고 제안해
검토 요청"*. 아래는 **내 제안**이다. 검토에서 뒤집히면 따른다.

### 2-1. 확인은 **견적 행**에 묶는다. 전역 카탈로그를 건드리지 않는다

```
⛔ data/approved/labor-mappings.json 의 confirmed 를 true 로 바꾸지 않는다
⛔ schema.ts 의 z.literal(false) 를 풀지 않는다
✅ 확인 사실은 QuoteRow 안에 둔다
```

**이유:** 배포 자료는 "자동 추출이고 미확인"이라는 사실을 그대로 유지해야 한다
(`buildLabor.ts:13` · 설계서 §5.3). 한 견적에서 확인했다고 **다른 모든 견적에서
확인된 것으로 바뀌면 안 된다.**

### 2-2. 확인은 **내용 지문**에 묶는다. 내용이 바뀌면 무효가 된다

`QuoteRow` 에 아래를 더한다.

```ts
laborConfirmation?: {
  /** 무엇을 보고 확인했는지 — 아래 값들을 이어 붙인 지문 */
  basisFingerprint: string;
  confirmedAt: string;        // ISO 날짜
};
```

**지문에 들어가는 것** (하나라도 바뀌면 확인이 풀린다):

```
laborItemId · 품셈 코드
직종별 공수 목록 (직종명 + 수량)
적용된 직종별 노임 + wageTableId
품목별 요율 · 할증
수량 (행의 quantity)
```

→ 품셈이 바뀌거나 노임이 갱신되면 **지문이 달라져 확인이 자동으로 무효**가 된다.
  사람이 "그때 그 숫자를 보고" 확인한 것이므로, 숫자가 바뀌면 다시 봐야 한다.

### 2-3. 세 가지 상태를 사람이 고른다

| 고르는 것 | 뜻 | 필요한 입력 |
|---|---|---|
| **확인함** | 품셈 연결과 계산 근거를 보고 맞다고 판단했다 | 없음 (지문이 자동 기록됨) |
| **직접 입력** (`manual`) | 품셈 대신 금액을 직접 넣는다 | 금액 + **사유**(설계서 §5.3) |
| **해당 없음** (`not-applicable`) | 이 행에는 노무가 들어가지 않는다 | **사유** |

- [ ] ⛔ **기본값은 어느 것도 아니다.** 아무것도 고르지 않으면 **차단이 유지**된다.
- [ ] ⛔ **일괄 확인 버튼을 만들지 않는다.** 행마다 사람이 본다.
      (설계서 §7.5 — 미확인을 확인 완료로 바꾸지 않는다)

### 2-4. 확인하기 전에 **근거를 보여준다**

고르기만 하는 화면이면 사람이 무엇을 확인했는지 모른다. **계산 과정을 펼쳐 보인다.**

```
HD PTZ Camera / BRC-AM7            품셈 7-11-1-방송용카메라

  통신관련기사      0.15 × 324,979 =  48,746.85
  통신관련산업기사   0.35 × 304,662 = 106,631.70
  통신설비공       0.20 × 316,875 =  63,375.00
  보통인부        0.31 × 172,698 =  53,536.38
                            합계  272,289.93
  × 품목별 요율 0.63              = 171,542
  × 할증 (없음)
  × 수량 1                       = 171,542

  노임 기준  26년 하반기 (가이드)        [확인함] [직접 입력] [해당 없음]
```

- [ ] 노임이 **어느 표에서 왔는지** 함께 보여준다. 배포본과 가이드가 다를 수 있다
      (`workspace.ts:135`).
- [ ] ⛔ 금액만 보여주고 고르게 하지 않는다.

## Task A — 확인 상태를 문서에 둔다

**Files:** `src/domain/quote/types.ts`, 저장·열기 스키마, 그 시험.

- [ ] **먼저 실패하는 시험을 쓴다.** 확인한 행의 품셈 공수를 바꾸면 **확인이 무효가 되는지**
      단언한다. 지금은 그 필드가 없어 시험이 컴파일되지 않는다.
- [ ] `QuoteRow` 에 `laborConfirmation` 을 더한다. §2-2 의 지문을 만든다.
- [ ] 지문 계산 함수를 **도메인에 둔다.** 화면에서 만들지 않는다.
- [ ] 저장 파일(`WorkFileV1`) allowlist 에 넣는다. **원가·매입처는 들어가지 않는다.**
- [ ] 되돌리기(undo) 대상에 포함한다. 문서의 일부이므로 다른 편집과 같이 되돌아간다.
- [ ] 저장 → 다시 열기 → 지문이 그대로면 **확인이 유지**되는지 시험한다.
- [ ] 저장 → 노임표 교체 → 다시 열기 → **확인이 풀리는지** 시험한다.

## Task B — 차단 판정을 확인 상태와 연결한다

**Files:** `src/domain/labor/calculateLabor.ts`, `src/domain/quote/priceQuote.ts`, 그 시험.

- [ ] `mapping-unconfirmed` 차단을 **행의 `laborConfirmation` 으로 푼다.**
      전역 `mapping.confirmed` 는 **그대로 `false` 로 둔다.**
- [ ] 지문이 **현재 계산 근거와 다르면** 차단을 유지한다. 풀지 않는다.
- [ ] `laborMode: 'manual'` 은 **금액과 사유가 모두 있을 때만** 차단을 푼다.
- [ ] `laborMode: 'not-applicable'` 은 **사유가 있을 때만** 차단을 푼다.
      노무비는 `0` 이 아니라 **해당 없음**으로 다룬다(설계서 §5.6 — `undefined` ≠ `0`).
- [ ] ⛔ **품셈이 없다는 이유로 자동으로 `not-applicable` 이 되지 않는다.**
      `unresolved` 인 채로 두고 사람이 고르게 한다.
- [ ] 역방향 시험: 확인 판정을 `() => true` 로 바꾸면 위 시험들이 **전부 실패**해야 한다.
