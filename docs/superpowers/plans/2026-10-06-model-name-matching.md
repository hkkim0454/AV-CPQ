## 5. 칸마다 **신뢰도가 다르다**

| 칸 | 뜻 | 처리 |
|---|---|---|
| `model` · `quoteSpec` | 이 제품의 모델명 | 후보로 올린다 |
| `quoteName` | 이 제품의 품명 | 후보로 올린다 |
| **`options.description`** | **설명. 다른 제품 이름이 섞인다** | **후보로만 올린다. 자동 연결하지 않는다** |

### ⛔ 설명 칸에서만 맞은 것은 **자동 연결하지 않는다**

```
VID-0139  XDM-DAN-M36   설명 `XDM-12, 20, 36 동일 적용`    ← XDM-12 를 찾으면 걸린다
VID-0028  RA-AT001      설명 `CR-N700전용`                 ← CR-N700 을 찾으면 걸린다
```

**부속품이 본체로 연결된다.** 단가도 품셈도 전혀 다르다.

- [ ] 설명 칸에서만 맞은 것은 **경고와 함께 후보 목록에 올린다.**
- [ ] 화면에 **어느 칸에서 맞았는지** 보여 준다.
- [ ] `WJD` 5건이 여기 해당한다. **자동으로 붙지 않고 후보로 뜬다.**
      지금은 아무것도 안 뜨므로 그래도 나아진다.

## 6. ⛔ 1건만 맞아도 **자동 연결하지 않는다** (Codex 지적 3)

```
24인치 모니터  →  TVD-0056   품명 `24인치 모니터` · 모델 `삼성, 24인치`
```

맞기는 맞는다. 그러나 **`24인치 모니터` 는 모델명이 아니라 일반 명칭**이다.
그 제품이라고 단정할 근거가 없다.

- [ ] **새 검색으로 찾은 것은 건수와 무관하게 전부 후보 제시**로 한다.
- [ ] 자동 연결은 기존 1~3 단계만 한다.
- [ ] 후보에 **맞은 칸과 맞은 글자**를 함께 보여 준다. 사람이 판단할 근거다.

> 자동 연결로 넓히려면 **사람이 확인한 별명 목록**이 필요하다. 이번 범위 밖이다.

## 7. Global Constraints

- 품명에서 모델명을 **뽑아내지 않는다.**
- 하이픈·언더스코어를 **경계로 인정하지 않는다.**
- 설명 칸에서만 맞은 것을 **자동 연결하지 않는다.**
- 새 검색 결과는 **전부 후보 제시**다. 자동 연결을 늘리지 않는다.
- 기존 1~3 단계의 **연결 대상 SKU 가 한 건도 바뀌면 안 된다.**
