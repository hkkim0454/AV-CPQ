## 4. 검색 규칙 — **전부 적는다** (Codex 2차 지적 3)

> 2판은 앞뒤 경계만 적었다. 내부 처리 규칙이 빠져 있었다.

### 4-1. 모델명을 패턴으로 바꾸는 방법

- [ ] **대소문자를 구분하지 않는다.** 기존 `normalizeModel` 과 같다.
- [ ] 모델명을 **영숫자·한글 덩어리**로 쪼갠다. 쪼개는 기준은 그 외 모든 글자다.
- [ ] 덩어리 **사이에만** 구분자를 허용한다. 허용 목록을 고정한다.

```
공백  -  _  /  ,  .  (  )
```

- [ ] 기존 `normalizeModel` 이 지우는 `" ” “ * #` 과 **목록을 맞춘다.**
      두 곳이 다르면 1~3 단계와 4단계가 서로 다른 글자를 같다고 본다.
- [ ] 곱셈 기호 `×`(U+00D7) 는 **`X` 로 바꾼다.** 지우지 않는다
      (`matchCatalog.ts:52` 와 같은 이유로, 지우면 `9×3` 이 `93` 이 된다).

### 4-2. 앞뒤 경계

```
앞:  (?<![0-9A-Za-z\-_])
뒤:  (?![0-9A-Za-z\-_])
```

**하이픈과 언더스코어를 경계로 인정하지 않는다.** 인정하면 접두·접미가 붙은
다른 제품에 걸린다.

### 4-3. 검증 (실측)

| 찾는 것 | 대상 | 1판 | **2판 이후** | 무엇을 보는가 |
|---|---|---|---|---|
| `MR-4S` | `MR-4S-4K` | ⛔ 걸림 | **안 걸림** | 접미사 |
| `A40` | `SRG-A40` | ⛔ 걸림 | **안 걸림** | 접두사 |
| `CS10` | `CS100` | 안 걸림 | 안 걸림 | 숫자 경계 |
| `24인치` | `124인치` | — | **확인 필요** | **숫자 경계** |
| `KIN-GHD` | `Locking HDMI Cable` | 안 걸림 | 안 걸림 | 단어 내부 |
| `MR-4S` | `MR-4S` | 걸림 | 걸림 | 정상 |
| `BRC-H800` | `12배줌, BRC-H800` | 걸림 | 걸림 | 정상 |
| `BLU-101` | `BLU-101, AEC/Bluelink지원` | 걸림 | 걸림 | 정상 |

- [ ] 위 8건을 **그대로 시험으로 넣는다.**

#### ⚠ `24인치` 가 `124인치` 에 걸리는 것은 **숫자 경계**다

2판에 *"한글 경계"* 라고 적었다. **틀렸다.** 앞 글자가 `1` 이므로 숫자 경계 문제다.

- [ ] **한글 경계는 따로 시험한다.** 예: `모니터` 가 `대형모니터` 에 걸리는지.
      한글은 `[0-9A-Za-z]` 에 들어가지 않으므로 **현재 규칙으로는 걸린다.**
      걸려도 되는지 정해야 한다.

### 4-4. 같은 SKU 가 여러 칸에서 맞은 경우

- [ ] 후보 목록에 **한 번만** 올린다.
- [ ] 다만 **어느 칸에서 맞았는지는 전부 보존**한다. `[model, 규격]` 처럼 적는다.
      사람이 판단할 근거이므로 하나로 줄이지 않는다.

### 4-5. 짧은 모델명 — `MIN_KEY_LENGTH = 5`

`matchCatalog.ts:137` 이 `return NO_MATCH` 로 **2·3 단계를 끊는다.** 새 4단계를
그 뒤에 두면 짧은 모델명(실측 42건)은 4단계에도 오지 않는다.

- [ ] **그대로 둔다.** 짧은 이름으로 넓게 찾으면 오탐이 더 늘어난다.
- [ ] 다만 **1단계 exact 는 `MIN_KEY_LENGTH` 앞에 있다**(`matchCatalog.ts:126-133`).
      짧은 이름도 정확히 같으면 지금처럼 맞는다. **이 동작을 깨뜨리지 않는다.**
- [ ] 짧아서 4단계로 가지 못한 건수를 **따로 보고**한다. 숨기지 않는다.

## 5. 칸마다 **신뢰도가 다르다**

| 칸 | 뜻 | 처리 |
|---|---|---|
| `model` · `quoteSpec` | 이 제품의 모델명 | 후보로 올린다 |
| `quoteName` | 이 제품의 품명 | 후보로 올린다 |
| **`options.description`** | **설명. 다른 제품 이름이 섞인다** | **후보로만 올린다. 자동 연결하지 않는다** |

### ⛔ 설명 칸에서만 맞은 것은 **자동 연결하지 않는다**

```
VID-0139  XDM-DAN-M36   설명 `XDM-12, 20, 36 동일 적용`    ← XDM-12 를 찾으면 걸린다
VID-0028  RA-AT001      설명 `CR-N700전용`                 ← CR-N700 을 찾으면 걸린다
```

**부속품이 본체로 연결된다.** 단가도 품셈도 전혀 다르다.

- [ ] 설명 칸에서만 맞은 것은 **경고와 함께 후보 목록에 올린다.**
- [ ] 화면에 **어느 칸에서 맞았는지** 보여 준다.
- [ ] `WJD` 5건이 여기 해당한다. **자동으로 붙지 않고 후보로 뜬다.**
      지금은 아무것도 안 뜨므로 그래도 나아진다.

```

그 제품이라고 단정할 근거가 없다.

- [ ] 자동 연결은 기존 1~3 단계만 한다.
- [ ] 후보에 **맞은 칸과 맞은 글자**를 함께 보여 준다. 사람이 판단할 근거다.

> 자동 연결로 넓히려면 **사람이 확인한 별명 목록**이 필요하다. 이번 범위 밖이다.

- 품명에서 모델명을 **뽑아내지 않는다.**

## Task 3 — 연결 대상을 **항목 성격별로** 비교한다 (Codex 2차 지적 2)

### ⛔ 2판의 "하나라도 달라지면 중단"은 과하다

2판에 *"하나라도 달라지면 중단한다"* 고 적었다. **그러면 이 기능 자체가 성립하지
않는다.** 후보를 **추가하는 것**이 목적이기 때문이다.

항목을 성격별로 갈라 본다.

| 수정 전 상태 | 수정 후에 허용되는 것 |
|---|---|
| **연결된 SKU 가 있다** | **그대로 유지.** 바뀌면 중단한다 |
| **후보가 여럿 있다** | **그 목록 그대로 유지.** 바뀌면 중단한다 |
| **아무것도 없다** | **후보가 생겨도 된다.** 단 연결된 제품은 여전히 **없어야** 한다 |

- [ ] 같은 구성도·같은 카탈로그로 **수정 전후를 돌린다.**
- [ ] 항목마다 **연결 SKU** 와 **후보 목록**을 받아 위 표대로 검사한다.
- [ ] 새로 생긴 후보는 **근거(맞은 칸·맞은 글자)를 사람이 검토**한다.
