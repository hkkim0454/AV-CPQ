# PowerPoint 구성도 분석 결과 — av-builder 변환기 참고 자료

작성: 2026-10-04
작성자: AV-CPQ 쪽
받는 쪽: **av-builder 개발 담당** (PPT → av-builder 변환기)
측정 대상: `구성도_DSR A타워 29층 메모리사업부장실_260807.pptx` (슬라이드 5장)

이 문서는 **요구사항이 아니다.** AV-CPQ 쪽에서 PPT 를 읽어본 실측 결과이며,
변환기를 만들 때 같은 조사를 반복하지 않도록 넘긴다. 판단은 av-builder 쪽에서 한다.

역할 경계는 `docs/interface/av-builder.md` §0 에 있다. **PPT → av-builder 는 av-builder 담당**이다.

## 2. ✅ 선은 좌표로 100% 복원된다

이게 가장 중요한 발견이다.

```
연결선 24개 (슬라이드 2)
  XML 에 결합 정보(stCxn/endCxn) 있음 :  2개
  양끝 좌표가 도형에 닿음              : 24개  ← 전부
  오차                                 : 0~8pt (대부분 0~3)
```

**사용자에게 "연결선을 도형에 붙여 그려라"를 요구하지 않아도 된다.**
눈으로 붙여 그리면 좌표가 맞는다. XML 결합은 없어도 된다.

구현 시 주의:

- **그룹 변환을 반드시 풀어야 한다.** 슬라이드 2에만 그룹 5개가 있고, 그 안의 도형은
  좌표가 상대값이다. `grpSpPr/xfrm` 의 `chOff`·`chExt` 로 스케일·오프셋을 계산해 누적한다.
- `flipH`·`flipV` 로 선의 시작/끝이 뒤집힌다. 무시하면 방향이 반대가 된다.
- 끝점 허용 오차 **14pt** 면 24/24 가 잡혔다.

---

## 3. ⚠ 어려운 것 — 어느 도형이 장비인가

선 끝이 장비 상자가 아니라 **포트 글자**에 걸린다.

```
[빨강] 4ch        → HDMIIN5~8
[빨강] HIS        → 2ch
[검정] OUT2(PGM)  → SDI IN IN3/4
```

`4ch`, `HDMIIN5~8`, `HIS`, `SV_OUT` 은 장비가 아니라 **포트 라벨**이다.

그리고 텍스트 74건을 뽑아 보면 세 가지가 섞여 있다:

```
장비    SRG-X40UH 4EA · 멀티포맷 매트릭스 XDM-12 · 8채널 스위처 V-80HD
포트    HDMIIN1/2 · IN3/4thu 아웃 · OUT2(PGM, AUX1)
메모    총 4CH : PC 1CH / 노트북 1CH… · * 카메라3대는 고정입력
```

**이것을 규칙으로 가르는 방법을 찾지 못했다.** 테두리 유무·크기·글자 길이 모두
일관되지 않는다. 제안은 §5 참조.

## 4. 선 색 ↔ 신호 종류 (사용자 확인 완료)

범례 색 견본이 그룹 안에 묻혀 자동으로 못 읽는다. 사용자에게 직접 확인한 값:

| 색 | 신호 | 슬라이드 2 가닥 수 |
|---|---|---:|
| `FF0000` 빨강 | **DP/HDMI** | 15 |
| `00B050` 초록 | **LAN** | 6 |
| `0000FF` 파랑 | **USB** | 2 |
| 검정 (`scheme:tx1`) | **SDI** | 1 |
| `00B0F0` 하늘 | **광** | 0 |
| `7030A0` 보라 | **A.AUDIO** | 0 |

전 슬라이드 합계: LAN 25 · DP/HDMI 18 · A.AUDIO 5 · USB 3 · SDI 2 = **53가닥**

av-builder 의 `lineTypes` 기본값과 색이 다르다(av-builder HDMI 는 `#ef4444`).
**색으로 맞추지 말고 매핑표를 두는 편이 안전하다.**

## 5. 제안 — 도형 스텐실

§3 의 "어느 도형이 장비인가" 를 **규칙이 아니라 데이터로** 푸는 방법이다.

자주 쓰는 장비를 **대체 텍스트에 식별자가 박힌 도형**으로 만들어 PPT 한 장에 모아 둔다.
사용자는 거기서 **복사해 붙인다.** 대체 텍스트도 함께 복사된다.

```
도형 우클릭 → 대체 텍스트
   eq-xlsx-451 | XDM-12
```

| | |
|---|---|
| 사용자 부담 | 네모를 새로 그리는 것보다 **빠르다**. 추가 입력 없음 |
| 변환기 | 대체 텍스트가 있으면 장비, 없으면 포트 글자·장식. **추측 0** |
| 화면 | 대체 텍스트는 **보이지도 인쇄되지도 않는다** |

장비 DB 674개를 전부 넣으면 찾기가 더 느려진다. 자주 쓰는 30~40개로 1장,
나머지를 분류별로 뒷장에 두는 구성을 사용자와 상의했다.

> 사용자는 **"드로잉이 매우 쉽고 익숙해서"** PowerPoint 를 계속 쓰기로 했다.
> 습관을 여러 개 요구하는 대신 **복사해 쓰는 것 하나**로 줄이는 것이 이 제안의 취지다.

## 6. 그 밖에 읽히는 것

**수량이 글자에 들어 있다**

```
SRG-X40UH4EA        → 4
27”모니터 * 25ea     → 25
TXCTR100슬롯4EA      → 4
삼성 MPF P1.6 (9x4)  → 9×4 (LED 모듈 배열)
```

패턴: `(\d+)\s*(?:EA|ea|대|개|SET)`. 띄어쓰기가 없는 경우가 많다.

**PDF 는 쓰지 말 것**

같은 구성도의 PDF 도 받아 비교했다. PDF 는 도형이 벡터 경로로 납작해져
**"이 선이 어느 도형과 어느 도형을 잇는지" 가 사라진다.** PPTX 만 쓴다.

**`openpyxl` 류의 왕복 저장 주의** (AV-CPQ 쪽 경험)

PPTX 를 읽기만 한다면 무관하다. 다만 쓰기가 섞이면 — ElementTree 로 OOXML 을
재직렬화할 때 등록되지 않은 네임스페이스 접두사가 `ns0`/`ns1` 로 바뀌고,
`mc:Ignorable="x14ac xr xr2 xr3"` 처럼 **속성 값 안에서 접두사를 문자열로 참조**하는
부분이 끊어진다. 파일이 열리지 않게 된다.

## 7. 분석 스크립트

AV-CPQ 저장소 `.local/` 에 있다(git 추적 대상 아님). 필요하면 가져가면 된다.

| 파일 | 내용 |
|---|---|
| `probe_names.py` | 도형 이름·대체텍스트·연결선 결합 여부 |
| `probe_rtcom.py` 외 | (무관 — 품셈 쪽) |

그룹 변환을 푸는 부분(`walk(node, tf)`)이 재사용할 만하다.
이 대화 기록에 전문이 남아 있다.

## 8. 요약

| | |
|---|---|
| ✅ 선 복원 | **좌표로 100%.** XML 결합 불필요 |
| ✅ 신호 종류 | 선 색으로 구분. 매핑표 §4 |
| ✅ 수량 | 글자에서 추출 가능 |
| ⚠ 장비 식별 | 포트 라벨·메모와 섞임. **스텐실로 해결 제안** (§5) |
| ❌ 포트 구성 | PPT 에 없음. **av-builder 장비 DB 에서 붙여야 함** |
| ❌ 옵션 카드 | PPT 에 없음. 같음 |

마지막 두 줄이 **이 변환기가 av-builder 안에 있어야 하는 이유**다.
PPT 를 아무리 잘 읽어도 포트와 옵션 카드는 장비 DB 에서만 나온다.
