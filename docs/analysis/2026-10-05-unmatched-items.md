#### 사용자 확인 (2026-10-05) — PC 는 **사양 차이**다

> **"1번은 pc사양에 따라 비용이 달라서 그래"**

`삼성 노트북 / i7급` 과 `삼성 데스크탑5 / i7급` 의 가격 차이는 **카탈로그 오류가 아니다.**
같은 `i7급` 이라도 사양에 따라 값이 다르다. **견적할 때 사양을 보고 사람이 고르는 것이 정상**이며,
프로그램이 자동으로 정할 대상이 아니다.

`삼성 데스크탑5` 는 셋이 **용도별로** 갈려 있기도 하다.

```
AUD-0080  노이즈제거용 PC   1,386,000   묶음 "노이즈 억제 솔루션"
HEC-0007  TCU 제어PC       1,386,000   묶음 "TCU"
CTL-0048  Desktop PC       1,441,000   묶음 "- Intel Core i5 …"
```

앞의 둘은 **값이 같고 용도만 다르다.**

#### ✅ 묶음 이름의 `i5` — **2026-10-05 해결됨. 추출 결함이었다**

> 아래는 처음에 *"사용자 확인이 필요하다"* 고 적었던 항목이다. **원본을 덜 읽은 판단이었다.**
> 하반기 품셈 원본을 직접 열어 확인한 결과 **제품명(`i7급`)이 맞고 묶음 이름이 밀린 것**이었다.

원본 `단종, 미사용 제품` 시트 283~291행이다. **사양 설명 줄이 제품 행 아래에 온다.**

```
283   Desktop PC   삼성 데스크탑5 / i5급     단위 EA
284     - Intel Core i5 / 16GB / 256GB SSD    단위 없음   ← 283 의 사양
285   Desktop PC   삼성 데스크탑5 / i7급     단위 EA
286     - Intel Core i7 / 16GB / 256GB SSD    단위 없음   ← 285 의 사양
```

`classifyRow.ts:73-78` 이 **단위 없는 행을 묶음 머리글로 분류**하고, `:145-147` 이
그것을 **이후 제품들**에 붙인다. 그래서 285행(i7급)이 284행(i5 설명)을 가져갔다.

**실측 영향: 전체 1,468건 중 37건(2.5%).**

#### ✅ 노트북 가격 차이도 함께 풀렸다

아래 §2 에서 *"같은 `i7급` 인데 값이 다르다"* 고 적었던 것의 답이다.

```
288   Notebook  삼성 노트북 / i7급
289     - Intel Core i7 / 16GB / 256GB SSD              → CTL-0051  1,430,000
290   Notebook  삼성 노트북 / i7급
291     - Intel Core i7 / 16GB / 256GB SSD / RTX2060    → CTL-0053  2,640,000
```

**둘째가 그래픽카드를 포함한 고사양 모델이다.** 품명만 보면 구분이 안 됐다.

→ 고치는 작업은 `docs/superpowers/plans/2026-10-05-pumsem-2026h2-migration.md`
  의 **Task 1-B** 로 옮겼다.

### ⛔ 발견한 결함 — **구분 정보가 있는데 화면에 안 보인다**

위 표의 "차이" 칸은 내가 지어낸 것이 아니다. **품셈 원본 D열(설명)에 적혀 있다.**

```
영상 시트 56행   V-160HD            설명 "아이패드 제외"              6,000,000
영상 시트 57행   V-160HD            설명 "아이패드 포함"              7,000,000
영상 시트 233행  Bridge UHD M_OTR   설명 "구형 / 양방향 / 1개 단품"     687,000  EA
영상 시트 234행  Bridge UHD M_OTR   설명 "신형 / 단방향 2채널 / 1개 SET" 1,134,000  SET
```

이 값은 **카탈로그에도 제대로 들어 있다** — `options['description']` 이다
(`buildProducts.ts:112`).

**그런데 후보를 고르는 화면이 그것을 보여주지 않는다.**
`WarningList.tsx` 의 `CandidateList` 는 두 갈래 모두 설명도 단가도 쓰지 않는다.

```
기본 분기 (70행)        {sku} — {quoteName}
  → "VID-0056 — HD Video Switcher"
    "VID-0057 — HD Video Switcher"          글자 하나 다르지 않다

묶음 분기 (102행)       {quoteSpec} ({sku})
  → "V-160HD (VID-0056)"
    "V-160HD (VID-0057)"                    역시 같다. 묶음도 둘 다 "비디오 스위처"
```

→ **사람이 100만 원 차이를 모르는 채로 둘 중 하나를 찍어야 한다.**
  `Bridge UHD M_OTR` 은 품명에 양방향/단방향이 들어 있어 그나마 갈리지만,
  단위가 `EA` 와 `SET` 으로 다른 것은 보이지 않는다.

#### 고칠 것 (구현 담당에게)

후보 목록에 **`options['description']` 과 단가, 단위**를 함께 보여준다.

```
VID-0056   V-160HD   아이패드 제외   6,000,000원 / EA
VID-0057   V-160HD   아이패드 포함   7,000,000원 / EA
```

자료는 이미 있다. **화면만 고치면 된다.** 새 추출도, 새 결정도 필요 없다.

#### ⛔ 내가 중간에 잘못 판단한 것

조사하다가 *"설명 칸이 카탈로그에 실리지 않았다"* 고 적었다가 **철회했다.**
제품 레코드의 **최상위 필드만 보고** `options` 안쪽을 열어 보지 않았기 때문이다.
`options['description']` 에 정상적으로 들어 있다. **추출 결함이 아니라 표시 결함이다.**

### 제안 — 10건은 경고를 낮출 수 있다

지금 코드는 모호 15건을 전부 `device-ambiguous-match` 로 막는다. **사람이 아무 의미 없는
선택을 10번 하게 된다.**

**단가·공수·품명·규격·단위가 전부 같을 때만** 첫 후보를 쓰고, 경고를 차단에서 안내로 낮추는
방안을 검토할 수 있다. **이것은 "조용히 추측"이 아니다** — 결과가 동일함을 먼저 확인한 뒤
고르는 것이고, 어느 SKU 를 썼는지 화면에 남긴다.

⛔ **다섯 건에는 절대 적용하지 않는다.** 구분 조건은 "묶음이 비슷해 보임"이 아니라
**"다섯 값이 전부 일치"** 여야 한다. 하나라도 다르면 지금처럼 막는다.

→ 구현 여부는 **사용자 승인 후** 결정한다. 이 문서는 근거만 제공한다.

### ⚠ 72건 중 일부는 **모델명이 아니다** — av-builder 쪽 자료 문제다

카탈로그에 추가해도 해결되지 않는다. **구성도 자료를 고쳐야 한다.**

```
"AMP 기능만 수행 시"      파워 앰프     ← 설명문이 모델명 칸에 들어갔다

"Ceiling Speaker"        실링 스피커    ← 제품 종류명. 모델 아님
"24인치 모니터"            모니터        ← 규격만 있음
(모델명 없음)              전자칠판       ← 비어 있음
```

### ⚠ 같은 제품을 두 가지로 적은 것

```
"TELEVIC D-Cerno"     델리게이트
"TELEVIC, D-Cerno"    델리게이트     ← 쉼표 하나 차이
```

→ 둘 다 미매칭이다. av-builder 자료에서 **표기를 하나로 모아야** 한다.

### 묶음으로 처리할 수 있는 것 — JBL CONTROL 실링 스피커 12종

```
CONTROL 412C/T  414C/T  416C/T  418C/T  419CS/T  424C/T
CONTROL 424LP   426C/T  426LP   440CS/T  447C/T
```

한 제품군이 통째로 빠져 있다. **품셈에 이 묶음을 한 번에 추가하면 12건이 한꺼번에 해소된다.**
