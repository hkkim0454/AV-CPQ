## 1. 왜 지금 추출기를 그대로 돌리면 안 되는가 — 실측

`tools/extract_catalog.py` 는 **열 번호를 상수로** 쓴다(`READ_COLUMNS`). 하반기 파일은 열이 밀렸다.

| 도구가 읽으려는 것 | 상반기 | **하반기** | 결과 |
|---|---|---|---|
| `materialUnitPrice: 7` (G) | 재료비 단가 ✅ | **원가 단가** (전부 공란) | 판매단가가 전부 미등록이 된다 |
| `remark: 12` (L) | 비고 | **노무비 금액** | 금액이 비고로 들어간다 |
| `laborCode: 16` (P) | 품셈 코드 ✅ | **제조사/구매처** | ⛔ **매입처가 카탈로그로 들어간다** |
| `itemRate: 17` (Q) | 품목별 요율 ✅ | **영업비고** | ⛔ **매입처 메모·고객 현장명이 들어간다** |
| 직종 열 `20, 22, …` (T, V…) | 직종 ✅ | 요율·할증·표준단가 | 공수가 전부 틀린다 |

실제로 들어 있는 값이다.

```
P열  "SONY/한국에빅스"  "AVER/에이엔티"  "UJ코리아"
Q열  "260728_단가확인"  "230307_단가확인 천안 총괄장실"   ← 고객 현장명
```

**저장소는 공개(PUBLIC)다.** 그대로 돌리면 매입처가 인터넷에 올라간다.

### 하반기 파일에 원가는 없다 (실측)

품목 **2,132행 전부 G열(원가 단가)이 비어 있다.** 파일 자체는 원가를 담고 있지 않다.
판매단가는 I열에 살아 있다.

## 3. Global Constraints

- **⛔ 열 번호를 상수로 쓰지 않는다.** 머리글 글자로 찾고, 못 찾으면 **중단**한다.
  0 으로 채우거나 빈 값으로 넘어가지 않는다.
- **⛔ 금지 머리글을 만나면 즉시 중단한다** — `제조사` · `구매처` · `영업비고` · `원가`.
  읽으려는 열의 머리글에 이 글자가 있으면 **추출 전체를 멈춘다.** 그 열만 건너뛰지 않는다.
- 원본을 저장하지 않는다. `wb.save()` 를 부르지 않는다(실측: openpyxl 왕복 저장은
  Excel 이 열지 못하는 파일을 만든다).
- 품셈 원본 파일을 **저장소에 넣지 않는다.** 업로드 폴더에 둔 채 읽기만 한다.
- `M/D` 와 `M/M` 을 섞지 않는다(D1 — 섞으면 약 20배 틀린다).
- `undefined` 는 미등록이고 `0` 은 0이다(설계서 §5.6).
- **LED 는 이번 범위가 아니다.** 사용자 지시 *"LED쪽 계산은 나중에 하자"*.
  `SKIP_SHEETS` 에 `LED전광판 계산` 을 **유지한다.** 하반기 파일에서 이 시트가
  `visible` 로 바뀌었으므로, **숨김 여부로만 거르면 들어온다.** 이름으로도 거른다.

## 4. 시범으로 이미 증명한 것 (2026-10-05)

영상 시트 하나로 먼저 해 보았다. `.local/trial_video_extract.py` 가 그 스크립트다.

```
읽은 행           424
  판매단가 있음     321
  품셈(공수) 있음    317
직종              17개
```

### 노무비 역산 — **305건 전부 일치, 불일치 0**

뽑아낸 **공수와 노임만으로 노무비를 다시 계산**해 파일의 노무비 단가와 맞췄다.

```
(직종별 공수 × 직종별 노임) 합계 × 품목별 요율 × (1 + 할증) = 노무비 단가
```

열을 하나라도 잘못 읽었으면 전부 틀렸을 것이다. **이 검산이 추출이 옳다는 증거다.**

> ⚠ 처음에 할증을 `×할증` 으로 계산해 4건이 틀렸다. `×(1+할증)` 이 맞다.
> `src/domain/labor/calculateLabor.ts:5` 가 이미 그렇게 적고 있었다. **자료가 아니라
> 내 검산이 틀렸던 것이다.**

### 사용자 확인 — 견적 결과가 맞다

`XDM-12` 1EA + `XDM-HI100` 1EA 로 견적을 만들어 보여 주었다.

```
직접비계   재료비 7,039,020 (잡자재비 138,020 포함)   노무비 397,749
간접비계   1,027,329   (DS 프로파일 9항목, 3항목 미적용)
합계      8,464,098
```

> 사용자: **"잘 맞아~ 그렇게 나오면 될거 같아"**

→ **품목 두 줄짜리 간단 견적에도 잡자재비를 붙이는 것이 맞다**는 확인으로 함께 기록한다.

## Task 1 — 추출기를 머리글 기반으로 바꾼다

**Files:** `tools/extract_catalog.py`, `tests/unit/extractColumns.test.ts`(또는 Python 쪽 시험).

- [ ] **먼저 실패하는 시험을 쓴다.** 금지 머리글(`제조사/구매처`)이 읽기 대상 열에 오도록
      만든 합성 시트를 넣고, 추출이 **중단되는지** 단언한다. 지금 코드로는 통과해 버린다.
- [ ] `READ_COLUMNS` 를 **머리글 찾기**로 바꾼다. 2행과 3행을 합쳐 본다
      (`재료비`+`단 가` 처럼 두 줄에 걸쳐 있다).
- [ ] 찾아야 할 머리글과 그 의미를 코드에 적는다.

```
품   명      → name          규 격  → spec        설 명 → description
단위         → unit
재료비 + 단 가 → materialUnitPrice   ← 판매단가
노무비 + 단 가 → laborUnitPrice
비 고        → remark
품목별 요율% → itemRate      할증 → surcharge     표준 단가 → standardUnitPrice
```

- [ ] **품셈 코드 열에는 머리글이 없다**(S열 2·3행이 비어 있다). `할증` 과 `품목별 요율%`
      의 **왼쪽**이라는 위치로 찾되, **그 열의 값이 `7-11-1-…` 모양인지 확인**한다.
      모양이 다르면 중단한다.
- [ ] 직종 열은 **2행에 직종 이름, 3행에 `M/D`/`M/M`** 인 열을 **훑어서** 찾는다.
      시작 번호를 상수로 두지 않는다. 하반기는 W(23)부터지만 또 밀릴 수 있다.
- [ ] 금지 머리글 검사를 넣는다. `제조사` · `구매처` · `영업비고` · `원가` 중 하나라도
      읽기 대상 열의 머리글에 있으면 **`SystemExit` 로 전체 중단**한다.
- [ ] 찾지 못한 머리글이 하나라도 있으면 **어느 시트의 무엇을 못 찾았는지** 적고 중단한다.
- [ ] `SKIP_SHEETS` 에 `LED전광판 계산` 을 유지한다. 하반기에서 `visible` 로 바뀌었으므로
      **이름으로 거르는 경로가 실제로 동작하는지** 시험한다.

## Task 2 — 노무비 역산 검증을 추출 과정에 넣는다

**Files:** `tools/extract_catalog.py` 또는 별도 검증 스크립트.

- [ ] 추출 직후 **모든 시트**에서 역산을 돌린다.
      `(공수 × 노임) 합계 × 품목별 요율 × (1 + 할증) = 노무비 단가`
- [ ] 일치율을 보고한다. **불일치가 있으면 어느 행인지 전부 적는다.**
- [ ] 불일치가 일정 수를 넘으면 **중단한다.** 열을 잘못 읽었다는 뜻이다.
- [ ] 역방향 시험: 열 하나를 일부러 옆으로 밀면 **역산이 실패하는지** 확인한다.
      실패하지 않으면 이 검증이 죽어 있는 것이다.
