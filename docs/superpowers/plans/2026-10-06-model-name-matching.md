## 2. ⛔ 품명에서 모델명을 **뽑아내지 않는다**

사용자 예시는 *"품명에서 모델명만 떼어내라"* 로 읽힌다. **그 방향은 안 된다.**

```
BLU-101, AEC/Bluelink지원     쉼표 앞이 모델명
12배줌, BRC-H800              쉼표 뒤가 모델명
```

**정반대다.** 위치로도, 구분자로도 규칙을 세울 수 없다. 떼어내려 하면 추측이 된다.

### 대신 — **av-builder 모델명을 기준으로 카탈로그에서 찾는다**

```
전       카탈로그 품명에서 모델명을 뽑아 av-builder 와 맞춘다   ← 추측이 필요하다
후       av-builder 의 모델명으로 카탈로그 품명 안을 찾는다      ← 추측이 없다
```

av-builder 쪽 모델명은 **확정된 목록**이다. 그것을 열쇠로 쓰면 뽑아낼 필요가 없다.

---

## 3. 어느 칸을 보는가

실측 결과 모델명이 **네 칸에 흩어져 있다.**

| 칸 | 예 |
|---|---|
| `model` | `12배줌, BRC-H800` |
| `quoteSpec` | 같음 (`model` 과 같은 값인 경우가 많다) |
| `quoteName` | `삼성, 24인치` |
| **`options.description`** | **`WJD-2DV`** ← 품명에는 없고 여기에만 있다 |

### ⚠ `options.description` 을 빼면 5건을 놓친다

```
HEC-0031   model = `2분배기`   description = `WJD-2DV`
HEC-0032   model = `4분배기`   description = `WJD-4DV`
HEC-0033 · HEC-0034 · HEC-0035   같은 모양
```

품명에 모델명이 **아예 없다.** 처음 측정할 때 이 칸을 빼고 재어 5건을 놓쳤다.

---

## 4. ⛔ 단순 포함 검사는 **오탐을 만든다** (실증)

기호와 공백을 모두 지우고 포함 관계만 보면 **단어 경계가 사라진다.**

```
찾는 것    KIN-GHD        →  기호 제거  →  kinghd
대상       Locking HDMI Cable  →  기호 제거  →  loc kinghd micable
                                                  ^^^^^^ 여기에 걸린다
```

**TV 모델명이 HDMI 케이블 5건에 걸렸다.** `CBL-0016` ~ `CBL-0020` 이다.

### 경계를 넣으면 사라진다

모델명을 영숫자 덩어리로 쪼개고, 사이에만 구분자를 허용하며, **앞뒤가 영숫자가
아닌 것**을 확인한다.

```
KIN-GHD   →   (?<![0-9A-Za-z]) KIN [구분자]* GHD (?![0-9A-Za-z])
```

이렇게 하면 `LocKINGHDmi` 안에서는 앞 글자가 `c` 라서 걸리지 않는다.

**사람이 골라야 한다.** 지금처럼 묻는다.

## 6. Global Constraints

- **품명에서 모델명을 뽑아내지 않는다.** av-builder 모델명을 열쇠로 쓴다.
- **단어 경계를 반드시 넣는다.** 넣지 않으면 `KIN-GHD` 오탐이 생긴다.
- 여러 건 걸리면 **지금처럼 사람에게 묻는다.** 첫 번째를 조용히 고르지 않는다.
- **어느 칸에서 맞았는지 기록한다.** 나중에 잘못 맞은 것을 추적할 수 있어야 한다.
- 기존 `exact` 580건이 **한 건도 바뀌지 않아야 한다.**

## Task 1 — 대조 방식을 넓힌다

**Files:** `src/app/workspace.ts` 또는 대조를 맡은 모듈, 그 시험.

> ⚠ **실제 대조 위치를 먼저 확인한다.** 위 경로는 추정이다. `exact` / `fragment` /
> `normalized` / `ambiguous` 를 나누는 코드를 찾아 거기에 넣는다.

- [ ] **먼저 실패하는 시험을 쓴다.** `BRC-H800` 과 `WJD-2DV` 가 맞는지 단언한다.
      지금 코드로는 실패해야 한다.
- [ ] 찾는 순서를 정한다.

```
1  model 이 정확히 같은가            (지금 동작 — 그대로 둔다)
2  네 칸 안에 경계를 지켜 들어 있는가  (새로 넣는다)
3  그래도 없으면 미매칭              (지금 동작)
```

- [ ] **2단계에서 맞은 것은 `exact` 로 표시하지 않는다.** 새 이름을 붙여 구분한다.
      화면에서 *"품명 안에서 찾았다"* 고 보이게 한다.

### 경계 규칙

- [ ] 모델명을 **영숫자·한글 덩어리**로 쪼갠다.
- [ ] 덩어리 사이에만 구분자(` `·`-`·`_`·`/`·`,`·`.`·`(`·`)`)를 허용한다.
- [ ] 앞뒤가 **영숫자가 아닌 것**을 확인한다.
- [ ] 대소문자를 구분하지 않는다.

### 검사할 칸 네 개

```
model · quoteName · quoteSpec · options.description
```

- [ ] **`options.description` 을 빼지 않는다.** 빼면 `WJD` 5건을 놓친다.
