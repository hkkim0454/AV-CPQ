# 범위·데이터 결정 기록

날짜: 2026-10-03
근거: 설계서 `docs/design-spec.md` v1.0 의 "미확정 운영 결정" / "구현 전 확인 사항" 해소
결정 주체: 사용자 (대화)

설계서는 요구사항의 기준이고, 이 문서는 설계서가 열어둔 선택지를 닫은 기록이다.
설계서와 충돌하면 **이 문서가 우선**한다 (날짜가 뒤다).

## D1 — 카탈로그 출처: 표준품셈 파일

| | |
|---|---|
| 파일 | `원가삭제_2026상반기_표준품셈_260408.xlsx` |
| 역할 | **제품 카탈로그 + 품셈 매핑 + 노임표** (세 가지가 한 파일) |
| 활성 제품 | **1,468개** (숨김 2시트 제외) |
| 판매단가 보유 | 1,442개 (98%) |
| 품셈코드 보유 | 1,347개 (87%) |

설계서 §4.4 는 이 파일을 "표준품셈 데이터베이스"로만 다뤘다. 실제로는 **제품 마스터**다.
→ 설계서 §6.1 `ProductVariant` 의 공급원이 확정됐다. 별도 카탈로그 구축 작업은 불필요하다.

### 제외 대상

- 숨김 시트 `LED전광판 계산`(88), `단종, 미사용 제품`(67)
- M열 제조사/구매처, N열 영업비고 — 어떤 산출물에도 포함하지 않는다
- 제품행이 아닌 행 (단위·단가가 빈 분류/브랜드 머리글 행)

## D2 — 가격 두 종류의 취급

설계서는 "원가"를 한 덩어리로 다뤘다. 실제로는 두 가지이고 취급이 다르다.

| | 매입가 | 판매단가 |
|---|---|---|
| 어디 | 사용자가 그때그때 올리는 **별도 원가표** | 품셈 파일 **G열** 1,442개 |
| 고객이 보나 | 아니오 | **예** — 견적서에 찍혀 나감 |
| 저장소 | ⛔ 절대 금지 | ✅ 허용 (D3) |
| 처리 | 메모리 전용 `PrivateCostSession`, 새로고침 시 소멸 | 배포 데이터 |

매입가 취급은 설계서 §8 그대로이며 변경 없다.

## D3 — 판매단가 공개: 허용. 단 파일은 분리한다

**결정: 전 품목 판매가표가 배포 산출물에 포함돼도 좋다.**

사용자 판단 근거: 판매가는 어차피 고객 견적서에 찍혀 나간다.
감수하는 위험: 전 품목 가격표가 **한꺼번에** 노출되면 경쟁사가 통째로 가져갈 수 있다.
사용자가 이 위험을 인지하고 선택했다.

### 단, 되돌릴 수 있게 만든다

```
data/approved/products.json   제품명·규격·단위·분류·브랜드·품셈코드   (1,468)
data/approved/prices.json     판매단가만                              (1,442)
```

**처음부터 두 파일로 나눈다.** 현재는 둘 다 배포한다.

나중에 "판매가는 가리자"로 바뀌면 → `prices.json` 을 배포에서 빼기만 하면 된다. 코드 수정 없음.
그때 앱은 단가를 `미등록` 으로 표시하고, 사용자가 품셈 파일을 올리면 채운다 (매입가와 같은 통로).

이 전환이 공짜인 이유: 설계서 §5.6 이 이미 "가격 미등록을 0원으로 처리하지 말고 확정을 차단하라"고
요구하므로, **가격 없는 상태는 어차피 구현해야 하는 정상 경로**다.

→ 한 파일에 섞지 말 것. 섞으면 이 선택이 비가역이 된다.

## D4 — 부자재 자동 추천: 1차 범위에서 제외

**결정: 설계서 §7 의 연결 그래프 기반 자동 추천을 1차에 넣지 않는다.**

이유:

1. 포트 데이터가 **어느 파일에도 없다.** 평택 견적서는 완성된 견적서지 장비 사양서가 아니고,
   품셈 파일은 가격·품셈표다. 장비별 단자 구성은 제조사 사양서를 모델마다 수작업 입력해야 나온다.
2. 설계서 §0 이 정의한 "웹 완성"은 *"다운로드 후 Excel 후편집 불필요"* 이지 *"케이블 자동 선택"* 이 아니다.
   사용자가 케이블을 직접 넣어도 그 조건은 충족된다.
3. 설계서 §7 자체가 "검증된 근거 없이 자동 확정하지 말라"를 반복 경고한다. 포트 데이터 없이
   만들면 **틀린 추천을 자신 있게 하는** 결과물이 된다.

영향: 설계서 §11 단계 5 전체, 인수기준 A05 가 1차 범위 밖으로 이동한다.

## D5 — 대신: 사용자가 작성하는 "연동 항목 표" (설계 합의, 작성 보류)

사용자 제안:

> 특정 제품과 연동해야 하는 항목을 서로가 이해할 수 있는 폼으로 만들어서 서로 정보를 전달한다.
> 예를 들어 UTP 전송기면 UTP 케이블이 반드시 필요한 조건을 내가 거기다 기입한다.

프로그램이 사양서에서 **추측**하지 않는다. 사용자가 **선언**하고 프로그램은 따른다.

### 합의된 폼

품셈 파일에 시트 하나를 추가한다. 사용자는 엑셀에서 작성한다.

| 주 제품 | 딸림 항목 | 반드시? | 1대당 수량 | 비고 |
|---|---|---|---|---|
| UTP 전송기 | UTP 케이블 | ✅ | *(비움)* | 거리 따라 |
| UTP 전송기 | UTP 수신기 | ✅ | 1 | |
| 75" 디스플레이 | 벽부 브라켓 | | 1 | |
| 파워앰프 8CH | 스피커 케이블 | ✅ | *(비움)* | |
| 42U 랙 | 랙 선반 | | 2 | |

**수량 칸이 비면 = 현장마다 다름.** 별도 표기 불필요.

### 두 축의 조합이 동작을 정한다

| 반드시? | 수량 정해짐? | 동작 |
|---|---|---|
| 예 | 예 | 자동 추가 |
| **예** | **아니오** | **자동 추가 + 수량 칸 비워 경고 표시 → 안 채우면 견적 확정 차단** |
| 아니오 | 예 | 추천만 (물어봄) |
| 아니오 | 아니오 | 추천만 (물어봄) |

"반드시 + 수량 미정"(UTP 케이블)이 이 기능의 핵심이다. 빠뜨린 채 고객에게 나가는 것을 막는다.
사용자가 `기존 공급` / `별도 공사` / `견적 범위 제외` 사유를 적으면 통과한다 (설계서 §7.5).

### 멱등성

사용자가 수량을 고치거나 삭제하면 프로그램이 다시 늘리지 않는다 (설계서 §7.3).

### 상태: **보류**

사용자 지시: *"특정 제품과 연동돼서 필요한 것들은 나중에 정리하는 걸로 해서 꼭 나한테 질문을 해 줘."*

→ 폼 설계는 위로 합의됐으나 **표 내용 작성은 하지 않았다.**
→ 구현 착수 전 반드시 사용자에게 질문한다. 임의로 채우지 않는다.
→ 제품 지정은 이름 타이핑이 아니라 **드롭다운 선택**으로 만든다 (오타·미등록 제품 방지).
→ 전수 작성 불필요. 자주 쓰는 10~20건만으로도 쓸모가 있다.

## D6 — 배포 방식: 미정

사용자 의사: *"개발 마친 이후에 깃허브에서 잠금처리할거야"*

⚠ 확인된 사실: **저장소를 private 로 바꿔도 GitHub Pages 로 배포한 사이트는 공개다.**
주소를 아는 사람은 `data/approved/*.json` 을 직접 받을 수 있다. 사이트 접근 제어는
GitHub Enterprise Cloud 기능이며 일반 계정에는 없다. 설계서 §1 의
"로그인 화면만 덧붙이고 공개 정적 파일에 비공개 가격을 넣지 않는다" 와 같은 맥락이다.

사용자는 이 사실을 안 상태에서 D3(판매가 공개 허용)를 선택했다. 따라서 배포 방식이
Pages 든 사내 전용이든 **D3 는 유효**하다.

배포 결정은 단계 8 로 미룬다. D3 의 파일 분리가 그때까지 선택지를 열어둔다.
